# Skill 安全扫描 Module 设计

## 1. 设计结论

安全扫描实现为可复用的 Python Module。调用方提供一个或多个 Skill 包的只读二进制内容及已编译规则集，Module 返回结构化扫描结果。Module 不依赖主机文件路径，不生成报告文件，不访问网络，不执行或落盘解压包内内容。

规则命中统一表示需要人工复核，不自动判定恶意、误报或最终合规。来源规则中不明确、不合理或可能误伤的语义保持可识别状态，不由实现自行修正。

| 能力 | 行为 |
|---|---|
| 本地安全检查 | 目标覆盖 96 条可本地执行规则。 |
| 已知恶意 IP/URL | `SEC-IOC-06/07` 记录在覆盖信息中；没有外部威胁情报数据时不执行，也不生成违规 finding。 |
| 输入 | 一个或多个 `PackageInput`，以及不可变的 `RuleSet`。 |
| 输出 | `ScanResult`，包含结论、finding、规则覆盖情况和包摘要。 |
| 规则调整 | 通过受版本控制的外置规则文档完成；扫描请求不能临时覆盖规则。 |
| 人工裁决 | finding 状态固定为 `REVIEW_REQUIRED`，人工结论由调用方另行记录。 |

## 2. Module 结构

| 项目 | 选择 |
|---|---|
| 语言 | Python 3.11 或更高版本。 |
| 项目与依赖管理 | 使用 uv；`uv.lock` 固化完整依赖解析结果。 |
| 运行依赖 | Pydantic 2 用于公开输入边界的严格运行时校验，其余使用标准库。 |
| 质量工具 | pre-commit 在提交前运行 mypy strict 和 Pydantic mypy 插件；Ruff、pytest 作为开发依赖。 |
| 规则格式 | JSON 兼容对象，并提供对应 Schema。 |
| 压缩包读取 | `zipfile` 对只读、可定位二进制流进行限量读取。 |
| 状态存储 | 无数据库；一次调用内的状态只保存在内存。 |
| 执行方式 | 多个包顺序扫描，保证资源可控和结果确定。 |

~~~text
PackageInput + RuleSet
          │
          ▼
SecurityScan Interface
    ├── Request Validator
    ├── Archive Reader
    ├── Fact Extractor
    ├── Detection Engine
    ├── Evidence Processor
    └── Result Builder
          │
          ▼
      ScanResult
~~~

`SecurityScan` 是唯一扫描入口。内部实现可以继续拆分，但调用方只依赖公开输入、结果和错误模型。

| 路径 | 职责 |
|---|---|
| `src/skill_security/__init__.py` | 导出稳定的公开 Interface 和模型。 |
| `src/skill_security/interface.py` | 实现公开 Interface：通过 Pydantic 严格校验请求字段，调用 Engine，失败时抛出 `ScanError`。 |
| `src/skill_security/models.py` | 包输入、规则集、finding、覆盖信息、结果和错误模型。 |
| `src/skill_security/rules.py` | 规则文档校验、编译、版本和执行计划。 |
| `src/skill_security/archive.py` | ZIP 条目枚举、限量读取和哈希。 |
| `src/skill_security/facts.py` | Token、URL、Base64、熵和隐藏字符等基础事实。 |
| `src/skill_security/detectors.py` | 受控匹配类型和组合检测算法。 |
| `src/skill_security/engine.py` | 独占完整扫描流程编排，包括执行顺序、事实复用、finding 汇总和去重。 |
| `src/skill_security/evidence.py` | 证据脱敏、截断和指纹。 |
| `src/skill_security/limits.py` | 通过 Pydantic 严格校验资源策略及硬上限。 |
| `config/security-rules.json` | 外置规则文档。 |
| `config/security-rules.schema.json` | 规则文档结构约束。 |
| `pyproject.toml`、`uv.lock` | 依赖声明、工具配置和可复现依赖锁定。 |
| `.pre-commit-config.yaml` | 提交前执行完整源码和测试类型检查。 |

## 3. Module Interface

### 3.1 公开操作

| 操作 | 输入 | 返回 | 作用 |
|---|---|---|---|
| 编译规则 | JSON 兼容的规则文档 | 不可变 `RuleSet` | 校验规则并生成确定的执行计划。 |
| 扫描 | `ScanRequest` | `ScanResult` | 对请求中的全部包执行完整安全扫描。 |

构造 `SecurityScan` 时必须提供不可变的 `ScanPolicy`，不存在隐式默认策略。构造时立即校验策略；同一实例不保存请求状态，可连续处理多个扫描请求。

请求字段和资源策略使用 Pydantic strict 模式校验，不执行字符串到数字等隐式转换。Pydantic 校验失败统一转换为不携带原始校验内容的 `ScanError`。

两个操作成功时返回表中结果，失败时统一抛出 `ScanError`，不返回错误对象或部分 `ScanResult`。

公开 Interface 不提供按次禁用规则、改变严重度、覆盖检测阈值、设置白名单或豁免 finding 的入口。

### 3.2 输入模型

| 模型 | 字段 | 约束 |
|---|---|---|
| `PackageInput` | 显示名称、只读二进制流、可选来源标识 | 二进制流必须可定位；Module 不关闭该流，并在成功或失败后恢复原始游标。 |
| `ScanRequest` | 一个或多个 `PackageInput`、`RuleSet` | 包列表不得为空；同一请求中的显示名称必须唯一。 |
| `RuleSet` | Schema 版本、规则版本、来源版本、规则 SHA-256、执行计划 | 只能由规则编译操作生成；创建后不可变。 |
| `ScanPolicy` | 条目、读取字节和 finding 等资源上限 | 构造 `SecurityScan` 时必需；创建后不可变，任何值都不得超过 Module 硬上限。 |

Module 按内容工作，不要求调用方提供本地路径。显示名称和来源标识只用于定位结果，不参与安全裁决。

### 3.3 结果模型

| 结果内容 | 说明 |
|---|---|
| 总体结论 | `PASS` 或 `REVIEW_REQUIRED`；发生扫描错误时不返回完整结果。 |
| 包摘要 | 显示名称、内容大小、ZIP SHA-256、条目数和 finding 数。 |
| finding | 稳定标识、规则信息、包内位置、脱敏证据、复核状态和规则提供的修改建议。 |
| 覆盖信息 | 已执行、未确认和未提供能力的规则 ID 与数量。 |
| 规则信息 | 规则版本、来源版本和规则 SHA-256。 |

结果不包含当前时间、主机路径或随机值。相同 Module 版本、输入内容、规则集和策略必须产生相同结果及排序。

### 3.4 职责分离

| Module 负责 | 调用方 Adapter 负责 |
|---|---|
| 规则语义校验和执行计划。 | 打开输入来源并管理流的生命周期。 |
| 包哈希、只读解析、事实提取和规则匹配。 | 从受控位置读取外置规则文档。 |
| finding 去重、稳定排序、证据脱敏和结论。 | 将结构化结果转换为所需报告格式并持久化。 |
| 返回结构化错误且避免泄露敏感内容。 | 将错误映射为具体接入方式的反馈语义。 |

## 4. 规则层

### 4.1 规则集内容

规则文档包含 Schema 版本、规则版本、来源文档版本、默认跳过目录、公共词汇表、规则清单及未提供能力清单。可疑 TLD、可执行扩展名和恶意关键词等公共词汇只定义一次，由规则引用。

每条规则至少包含：

| 字段 | 说明 |
|---|---|
| 规则 ID、检测器、检测项 | 使用原有 `SEC-*` 标识和来源名称。 |
| 来源描述、严重度 | 原样保留，不归一化复合严重度。 |
| 确认状态 | `APPROVED`、`UNRESOLVED` 或 `UNSUPPORTED`。 |
| 作用域和文件选择 | 文件名、文本行、文件或整个 ZIP，以及适用和跳过条件。 |
| 匹配类型和参数 | 由内置算法解释。 |
| 证据策略 | 指定脱敏、截断和展示方式。 |
| 修改建议 | 只采用来源规则或已审核规则配置中的内容。 |
| 来源限制 | 记录未定义的大小写、边界或范围，不改变规则行为。 |

只有 `APPROVED` 规则进入执行计划。来源语义未确认时保持 `UNRESOLVED`；缺少必要外部数据或能力时保持 `UNSUPPORTED`。二者仅出现在覆盖信息中。

### 4.2 匹配类型

规则文档只能选择受控的内置匹配类型：

- 字面量、关键词、独立 Token 和定长前缀 Token。
- 字段赋值、函数调用、调用链、顺序模式和转义序列。
- 文件名关键词和双重扩展名。
- Base64、熵、隐藏字符、URL 和域名。
- JSON 特定字段和多事实组合条件。

规则文档不接受 Python、Shell、动态模块、任意可执行表达式或任意正则。参数外置，算法保留在 Detection Engine，避免代码注入、ReDoS 和不可审计语义。

### 4.3 校验与治理

规则编译必须验证 Schema 版本、唯一 ID、状态、严重度、作用域、匹配参数、公共词汇引用和执行能力。规则 SHA-256 基于规范化 JSON：对象键递归排序、数组顺序保留、使用 UTF-8 编码、不保留无意义空白，并拒绝非有限数值。结果中同时保留规则版本和该哈希。

规则变更必须更新规则版本、对应正反测试样例并经过人工审核。实现不能为了减少误报而修改来源规则的大小写、边界、范围、严重度或检测条件；需要调整时先把问题标为 `UNRESOLVED`，再通过规则评审形成新版本。

## 5. 数据处理与扫描流程

每个包记录显示名称、内容大小和 SHA-256。包内条目记录原始路径、扩展名、声明大小和实际读取范围。文件名规则检查已枚举条目；内容规则只处理规则选中的文本条目。

支持的文本条目使用 UTF-8 严格解码。无法解码、加密、CRC 错误或读取失败均使本次扫描失败，不能静默跳过或返回 `PASS`。

公开 Interface 完成输入模型校验后，把不可变请求交给 Engine。以下扫描顺序由 Engine 独占编排：

1. 校验规则集状态和资源策略，建立执行上下文。
2. 逐个计算包哈希并打开 ZIP。
3. 枚举条目并执行文件名规则。
4. 限量读取文本内容并建立行索引。
5. 一次提取 Token、URL、Base64、熵和隐藏字符等基础事实。
6. 执行逐行、文件级和结构化文件规则。
7. 第二遍执行需要组合事实的规则。
8. 对 finding 去重、排序、脱敏并生成稳定标识。
9. 汇总包摘要、规则覆盖信息和总体结论。

同一行的 URL、Base64、熵和隐藏字符只分析一次，再将事实映射到相关规则。涉及压缩、上传、敏感目录和递归枚举的规则先记录单项事实，再按来源规则定义组合。

资源保护遵循既定 `ScanPolicy`，至少包括：每个 ZIP 最多处理 1000 个条目、每个文本文件最多读取前 64KB、限制累计读取量和 finding 数量、不递归扫描嵌套 ZIP、不跟随包内链接。超过上限时返回错误，不能把未完成扫描当作无 finding。

## 6. Finding 与证据

Finding ID 的输入依次为 ZIP SHA-256、规则 ID、包内路径、行号、列号和证据指纹。该序列按与规则哈希相同的规范化 JSON 编码后计算 SHA-256，避免字段拼接歧义。证据指纹只使用脱敏后的类型、位置、长度和分类信息，不对密码、密钥、Token 或私钥正文计算可供离线猜测的哈希。每个具体命中形成一个 finding，并按包、路径、位置和规则 ID 固定排序。

| 字段组 | 字段 |
|---|---|
| 输入信息 | Skill 包显示名称、来源标识、ZIP SHA-256。 |
| 规则信息 | 规则版本、规则 SHA-256、规则 ID、检测项、来源描述、严重度。 |
| 位置和证据 | 包内文件、行号、列号、脱敏证据和证据指纹。 |
| 处置信息 | `REVIEW_REQUIRED`、规则提供的修改建议。 |

规则没有经过审核的修改建议时，相应字段保持为空，Module 不根据命中内容自行生成修复结论。

| 证据类型 | 返回策略 |
|---|---|
| 密码、Token、私钥 | 不返回正文，只记录类型和长度；Token 可保留固定前缀。 |
| 用户名 | 保留少量前缀，其余掩码。 |
| Base64 | 记录长度、解码分类和恶意关键词分类。 |
| 高熵文本 | 记录行长、熵值和阈值。 |
| URL | 删除疑似凭证查询参数。 |
| 普通命令 | 截断到固定长度并移除换行。 |

Module 返回与输出格式无关的结构化字段。Adapter 负责报告格式、输出环境所需的转义和持久化，但不得改变 finding 内容或裁决。

## 7. 错误与安全约束

| 错误码 | 场景 |
|---|---|
| `REQUEST_INVALID` | 包列表为空、名称冲突或输入模型无效。 |
| `POLICY_INVALID` | `ScanPolicy` 缺失、取值无效或超过 Module 硬上限。 |
| `RULESET_INVALID` | 规则结构、引用、状态或执行能力无效。 |
| `PACKAGE_SOURCE_INVALID` | 二进制流不可读或不可定位。 |
| `ZIP_OPEN_FAILED` | 内容不是有效 ZIP，或 ZIP 无法打开。 |
| `ZIP_ENTRY_READ_FAILED` | 条目加密、CRC 错误、读取失败或文本解码失败。 |
| `RESOURCE_LIMIT_EXCEEDED` | 达到条目、读取量或 finding 上限。 |

`ScanError` 包含稳定错误码、可选包显示名称、可选包内路径和经过清理的说明，不包含密码、密钥、Token、私钥或完整可疑内容。规则编译、构造或扫描失败均通过该异常报告。任一包失败时不返回完整 `ScanResult`；调用方不能把部分结果表示为完整扫描结论。

Module 必须保持以下安全约束：

- 不执行包内内容，不调用落盘解压。
- 不访问网络，不查询外部威胁情报源。
- 不递归处理嵌套压缩包，不跟随包内链接。
- 不修改输入流内容，结束时恢复调用前的流位置。
- 不写入报告、临时扫描文件或持久化状态。

## 8. 测试、验收与规模

测试必须覆盖：

- 公开 Interface、策略注入、输入所有权、流位置恢复和 `ScanError`。
- 每种匹配类型，以及每条 `APPROVED` 规则的正例和反例。
- 已知误报样例，确保来源规则不会被实现静默修正。
- 非法规则、损坏或加密 ZIP、资源超限和 UTF-8 失败。
- 规则规范化哈希、密钥脱敏、finding 稳定标识、去重和排序。
- 多包扫描失败时不返回完整结论。
- 两个现有 Skill ZIP 的端到端回归。
- `uv lock --check`、`uv run mypy` 和 `uv run ruff check src tests` 必须通过。
- 安装本地 hook 后，未显式跳过的当前 clone 提交执行完整 mypy strict 检查；不可绕过的门禁需要 CI 或服务端策略。

验收结果应满足：

- 目标本地规则均有确定的匹配定义和测试。
- `SEC-IOC-06/07` 不参与本地扫描，只在覆盖信息中准确说明能力状态。
- 相同输入内容、规则集和策略产生相同结果。
- finding 只表示安全规则命中，状态均为 `REVIEW_REQUIRED`。
- 每条 finding 可追溯，且不泄露完整密码、密钥、Token 或私钥。
- 扫描错误不能被表示为 `PASS`，Module 不产生任何输出文件。
- 依赖必须与 `uv.lock` 一致，源码和测试必须通过 mypy strict 及 Pydantic mypy 插件检查。

| 内容 | 预计非空有效行 |
|---|---:|
| Module、规则编译、ZIP、事实和检测实现 | 800—1100 |
| 外置规则和公共词汇表 | 1000—1300 |
| 测试代码和规则案例 | 1200—1700 |
| 总计 | 3000—4100 |

实施顺序为：公开模型和 Interface、规则编译、ZIP 只读、基础事实、检测引擎、证据与结果、外置规则、端到端回归。规则语义已经确认时预计 6—8 人天；需要逐条确认大小写、边界和文件范围时预计 8—10 人天。
